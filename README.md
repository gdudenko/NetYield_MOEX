# 🏦 NetYield MOEX

**Калькулятор чистой доходности облигаций Московской биржи** с учётом налогов,
оферт, погашений, ликвидности и сценариев изменения ключевой ставки ЦБ РФ.

[![Python](https://img.shields.io/badge/Python-3.12+-blue.svg)](https://www.python.org/)

> ⚠️ **Дисклеймер:** проект создан в образовательных целях и не является
> индивидуальной инвестиционной рекомендацией.

## ✨ Возможности

- 📊 **Анализ ОФЗ и корпоративных облигаций** голубых фишек и квазигосударственных эмитентов
- 💰 **Расчёт чистой доходности** с учётом НДФЛ 13% и налоговых льгот ОФЗ
- 🛡️ **Защита от ловушки оферты** — бумаги с офертой внутри периода владения исключаются
- 📅 **Учёт погашений** — если бумага погашается внутри периода, считается возврат номинала
- 📈 **Три сценария ключевой ставки** (оптимистичный / базовый / пессимистичный) с расчётом цены через дюрацию
- 🔍 **Классификация купонов** по официальным полям Мосбиржи: фиксированный / переменный / флоатер
- 💧 **Фильтр ликвидности** по количеству сделок и обороту
- 🖥️ **Два интерфейса**: консольный и графический (GUI с сортировкой, поиском и календарём)
- 🏦 **Автоматическое получение ключевой ставки ЦБ РФ** через SOAP API
- 📝 **Полное логирование** всех событий в файл `net_yield.log`

## 📥 Скачать готовый EXE (Windows)

Готовые сборки публикуются в **[GitHub Releases](../../releases)**.

1. Перейдите на вкладку **Releases** в репозитории
2. Откройте последний релиз
3. Скачайте архив **`NetYield_MOEX-windows.zip`**
4. Распакуйте архив в любую папку
5. Запустите **`NetYield_MOEX.exe`** двойным кликом

> 💡 Python на целевом компьютере **не нужен** — всё уже внутри сборки.
> Для работы требуется только доступ в интернет (данные ЦБ РФ и Мосбиржи).

Рядом с exe будут создаваться файлы:
- `net_yield.log` — журнал работы программы
- `net_yield_result.csv` — результат последнего расчёта

## 🔧 Установка из исходников

### Требования

- Python **3.12+** (для сборки EXE — строго 3.12)
- Доступ в интернет
- ОС: Linux / Windows / macOS

### Установка

```bash
# Клонируем репозиторий
git clone https://github.com/gdudenko/NetYield_MOEX.git
cd NetYield_MOEX

# Создаём и активируем виртуальное окружение
python -m venv venv
source venv/bin/activate        # Linux / macOS
# venv\Scripts\activate         # Windows

# Устанавливаем зависимости для запуска
pip install -r requirements.txt
```

Зависимости нужны только для сборки exe и разработки (pillow, pyinstaller):

```bash
pip install -r requirements-dev.txt
```

Иконки лежат в репозитории, генерировать их заново обычно не нужно.
Если всё-таки нужно:

```bash
python tools/make_icon.py
```

## 🧮 Как считается доходность

### Основные формулы

**Купоны за период:**

```
Купоны = Номинал × (Купон% / 100) × (Дней владения / 365)
```

**Налог:**

```
ОФЗ:        Налог = Купоны × 13%
            (прибыль/убыток с тела НЕ облагается — льгота на дисконт)
Корпорат:   Налоговая база = Купоны + Прибыль с тела
            Налог = max(База, 0) × 13%   (сальдирование убытков)
```

**Чистый доход:**

```
Режим "Продажа":   Доход = (Купоны − Налог) + (Цена продажи − Цена покупки)
Режим "Погашение": Доход = (Купоны − Налог) + (Номинал − Цена покупки)
```

**Доходность:**

```
За период:  (Доход / Цена покупки) × 100
Годовая:    (1 + Доходность за период / 100) ^ (365 / Дней) − 1
```

### Сценарии изменения ставки

Цена облигации при продаже прогнозируется через **дюрацию**:

```
ΔЦены (%) ≈ −Дюрация (лет) × ΔСтавки (%)
```

| Сценарий        | Δ ставки | Эффект                |           
|-----------------|----------|-----------------------|
| Оптимистичный   | −2 п.п.  | Цены облигаций растут |
| Базовый         | 0 п.п.   | Цены не меняются      |
| Пессимистичный  | +2 п.п.  | Цены облигаций падают |

> Чем больше дюрация бумаги, тем сильнее её цена реагирует на ставку.
> Короткие бумаги и флоатеры почти не чувствительны к сценарию.

### Классификация купонов

Тип купона определяется по официальному полю Мосбиржи `COUPON_DETAILS`:

| Значение поля                                                                      | Класс         | Поведение в расчёте           |
|------------------------------------------------------------------------------------|---------------|-------------------------------|
| `Фиксированный с известными купонами`                                              | Фиксированный | Купон из данных биржи         |
| `Фиксированный с неизвестными купонами`                                            | Переменный    | Текущий купон из данных биржи |
| `Ключевая ставка`, `Ставка RUONIA`, `Индекс RUONIA`, `Срочная ставка RUONIA 3m/6m` | Флоатер       | Прогноз = текущая ставка ЦБ   |
| `ИПЦ`                                                                              | Неизвестный   | Купон из данных биржи         |

## 🛡️ Фильтры и защита от ловушек

Последовательность фильтров в `analysis/filters.py`:

1. **Белый список эмитентов** — только голубые фишки и квазигосы (для корпоративных бумаг)
2. **Чёрный список** — исключаются субординированные, конвертируемые и прочие рискованные выпуски
3. **Тип облигации (`BONDTYPE`)** — исключаются структурные, конвертируемые, валютные
4. **Подвид (`BONDSUBTYPE`)** — исключаются бессрочные (вечные суборды)
5. **Ликвидность** — не менее N сделок ИЛИ оборота за день
6. **Ловушка оферты** — исключаются бумаги, у которых оферта попадает внутрь периода владения

### Почему оферта — это ловушка

В день оферты цена облигации принудительно стремится к номиналу, а эмитент
может объявить новый купон произвольного размера. Если оферта попадает внутрь
вашего периода владения, прогноз цены становится ненадёжным — такие бумаги
скрипт исключает автоматически.

## 📝 Логирование

Все события пишутся в файл **`net_yield.log`** рядом с проектом (или рядом с exe).

| Уровень   | Куда           | Что попадает                                         |
|-----------|----------------|------------------------------------------------------|
| `DEBUG`   | Только файл    | Детали: причины отсева бумаг, содержимое ответов API |
| `INFO`    | Консоль + файл | Основные события: загрузка, фильтры, итоги           |
| `WARNING` | Консоль + файл | Нештатные ситуации: резервная ставка, пустые выборки |
| `ERROR`   | Консоль + файл | Ошибки с полным трейсбеком (`exc_info=True`)         |

Уровни настраиваются в `app_config.py`:

```python
CONSOLE_LOG_LEVEL = 'INFO'    # или DEBUG для полной отладки в консоли
FILE_LOG_LEVEL = 'DEBUG'
```

Ошибки логируются с трейсбеком и контекстом через `error_handler.py`,
поэтому в логе всегда видно, **что** сломалось, **где** и **с какими данными**.

## 📦 Сборка EXE

> ⚠️ PyInstaller не поддерживает кросс-компиляцию: `.exe` собирается
> **только на Windows** (локально или через GitHub Actions).

### Автоматически (рекомендуется)

Сборка запускается в GitHub Actions на `windows-latest` и публикуется
в Releases. См. раздел [Релизы](#-релизы).

### Вручную на Windows

```bat
pip install -r requirements.txt
pip install -r requirements-dev.txt

pyinstaller --noconfirm --onedir --windowed --name NetYield_MOEX ^
    --icon=app_icon.ico ^
    --add-data "app_icon.ico;." ^
    --add-data "app_icon.png;." ^
    --paths=. ^
    --hidden-import=app_config ^
    --collect-data customtkinter ^
    --collect-data tkcalendar ^
    run_gui.py
```

> ⚠️ Разделитель в `--add-data` зависит от ОС: `;` в Windows, `:` в Linux/macOS.
> Этот формат строки — Windows. В workflow GitHub используется PowerShell,
> где перенос строки внутри команды не нужен, вся команда пишется в одну строку.

Результат: `dist/NetYield_MOEX/NetYield_MOEX.exe`

| Флаг                             | Зачем                                                             |
|----------------------------------|-------------------------------------------------------------------|
| `--windowed`                     | Без чёрного окна консоли                                          |
| `--onedir`                       | Папка с exe: быстрый старт, меньше ложных срабатываний антивируса |
| `--icon=app_icon.ico`            | Иконка exe                                                        |
| `--add-data` (иконки)            | Иконка окна доступна изнутри сборки                              |
| `--hidden-import=app_config`     | Гарантирует, что конфиг попадёт в бандл                           |
| `--collect-data customtkinter`   | Темы CTK (JSON) внутри сборки                                     |
| `--collect-data tkcalendar`      | Локали календаря (русские месяцы)                                 |

### Проверка собранного exe

После сборки exe обязательно прогоняется smoke-тест — он запускает
**собранный** бинарник и проверяет, что все модули приложения
попали в бандл, иконки на месте, а точка входа вызываема:

```bat
pyinstaller --noconfirm --onedir --console --name smoke_test ^
    --icon=app_icon.ico ^
    --add-data "app_icon.ico;." ^
    --add-data "app_icon.png;." ^
    --paths=. ^
    --hidden-import=app_config ^
    --collect-data customtkinter ^
    --collect-data tkcalendar ^
    smoke_test.py

dist\smoke_test\smoke_test.exe
```

Успех — строка `SMOKE TEST PASSED` и код возврата 0. Ненулевой код
останавливает сборку в CI, релиз не публикуется.

> **Почему это обязательно.** PyInstaller **не падает** на сломанном
> модуле: он компилирует синтаксис лениво, битый файл молча выпадает
> из бандла, и сборка завершается словами `Build complete!`. Пользователь
> получает exe, который падает с `ModuleNotFoundError` при запуске.
> Smoke-тест — единственное, что это ловит.

> **Не используйте `importlib.import_module` в smoke-тесте.** PyInstaller
> анализирует импорты статически и динамические в бандл не кладёт: сборка
> пройдёт, а на запуске будут отсутствовать десятки модулей. Импорты
> должны быть литеральными (`import X`).

## 🔧 Возможные проблемы

| Проблема                               | Решение                                                                              |
|----------------------------------------|--------------------------------------------------------------------------------------|
| Exe молча не запускается               | Запустите `smoke_test` (см. [Сборка EXE](#проверка-собранного-exe)) — он назовёт сломанный модуль |
| `ModuleNotFoundError` при запуске exe  | Сборка битая: пересоберите с нуля (`rm -rf build dist *.spec`) и убедитесь, что модуль не пуст и без синтаксической ошибки |
| `Build complete!`, но exe сломан       | Так PyInstaller и ведёт себя с битым модулем — ориентируйтесь на smoke-тест, а не на сборку |
| Календарь без русских месяцев          | Добавьте `--collect-data tkcalendar`                                                 |
| «Не удалось получить ставку ЦБ»        | Используется резерв из `app_config.py`; проверьте интернет и `net_yield.log`         |
| Антивирус ругается на onefile          | Используйте `--onedir` и распространяйте zip папки                                   |
| PyInstaller не поддерживает ваш Python | Для сборки используйте Python 3.12                                                   |
| Эмодзи не отображаются в GUI           | Особенность шрифтов tkinter; на расчёты не влияет                                    |
| Таблица пустая                         | Ослабьте фильтры ликвидности в `app_config.py` или расширьте белый список           |
